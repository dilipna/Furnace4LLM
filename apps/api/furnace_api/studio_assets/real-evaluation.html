Furnace’s current Studio runtime validates its infrastructure fixture. No real research-model adapter is implemented or validated in Studio yet. Selecting a model adapter is refused; Furnace never silently replaces it with a mock.

1. Check which path exists

  • Studio fixture — implemented and tested: local Docker, deterministic uppercase output, exact-string checks. No learned model, model latency, GPU experiment or model-quality result.
  • Existing CLI endpoint adapters — implemented: furnace-bench can call OpenAI-compatible, vLLM, SGLang and Ollama endpoints. Historical pinned vLLM measurements are separate saved evidence. Your own endpoint/model combination has not been validated here.
  • Native research-model loading — planned: a reviewed model-specific adapter, dependencies/checkpoint provenance, isolation and author-reference inference are still required. A configuration file or paper title does not prove compatibility.

2. Supply a reproducible contract

In Model contract, record the exact code/checkpoint revision and license, preprocessing/tokenizer, input/output signature, task, device/memory, loading command and session-state reset behavior. Supply a sanitized reference input and author-verified output, plus invalid-input and restart cases. Free inspection only reads metadata; it does not load or audit the model.

Before performance comparison, pin a baseline and candidate revision, keep workload/hardware/serving settings identical and declare the acceptance rule. A successful inference smoke is not evidence of improved quality or speed.

3. Run a bounded real-endpoint smoke

Prerequisite: an explicitly identified, already running server that performs real inference for a model you are authorized to use. Review its loading code and weights first. No model server is bundled or automatically provisioned. Run these commands from a source checkout with Python 3.12 and uv:

uv sync --frozen
uv run furnace-bench run --base-url http://127.0.0.1:8000/v1 --model YOUR_PINNED_MODEL_ID --adapter openai_compat --levels 1 --n 3 --warmup 1 --repeats 1 --input-tokens 32 --output-tokens 8 --length-mode natural --no-gpu --out first-model-check

Replace the endpoint and model ID with your reviewed local server. This performs three measured requests plus one warmup at concurrency one. --no-gpu disables local GPU telemetry; inference may still use the server’s GPU. A natural output length is an upper bound. Stop if the server is not yours or its identity is uncertain.

Inspect first-model-check/<run-id>/report.json and requests.jsonl. Require three successful, nonempty measured responses, no request errors, the intended target/model and a separately verified reference answer from that same server. The CLI’s exit code alone is insufficient: it can write a report containing failed requests. No mock server belongs in this real-model validation procedure.

This command measures client-observed serving behavior on synthetic prompts, not task accuracy, a model speedup, or a portable architecture certification. No automatic comparison/verdict is implied. For task-quality or baseline/candidate acceptance, use representative author-reviewed cases and repeated controlled measurements.

4. Know what remains

No live real-model validation was performed for this milestone: Studio lacks a research-model adapter and no identified Furnace inference server is running in the reviewed environment. The missing prerequisite for the CLI smoke is a pinned, authorized live model endpoint with a reference output. No compute was purchased and no mock was substituted.

Next: review the pinned model contract and endpoint, run the bounded smoke, then implement/validate the isolated Studio adapter against its reference behavior. Record load, inference, invalid input, timeout, reset, restart, cleanup and task-quality evidence before claiming support. Billing, remote provisioning and native installation are outside this preview.
