Use a server you already operate on this machine. Furnace sends bounded, non-streaming chat requests; it does not download weights, load research code or start the model server. No model combination has been validated yet.

Separate from the guided fixtureThe fixture uppercases text in Docker. This path observes responses from your chosen HTTP server. Its advertised model and your declared revision are not proof of which weights ran. Never use secrets or production prompts.

1. Choose a project

Create or inspect a project in the workspace first. The guided example is fixture metadata, not a model; prepare cases appropriate to your server before evaluating.

2. Describe your server

No Docker is required for this connector. A running, unauthenticated OpenAI-compatible text-chat server is required. Only http://127.0.0.1:PORT/v1 is accepted; no remote hosts, credentials, redirects or environment proxies. Saving makes no network request.

3. Confirm and connect

The connection check reads the server's model list. It does not establish inference or model quality. Reconnect after changing the contract, cases, preferences or connection, or restarting Studio.

Disconnecting never stops or uninstalls your external server. Furnace cannot cancel generation already running there. It bounds its own connection and stops issuing more requests.

Raw prompt/output is not stored in activity or evaluation records. Saved case text and expectations are included in exports.

5. Evaluate saved cases

Cases come from Workspace → Evaluations. Their fixture results are separate. Exact string equality is not semantic answer quality. Descriptive expectations stay unscored. Token-limit termination is incomplete, even if its text matches. The batch stops on a request failure or after 30 seconds; missing cases never pass.

Durations are client-observed non-streaming HTTP round trips, not TTFT or a model speedup. No baseline comparison, semantic judge, session-state isolation or architecture certification is implied.
