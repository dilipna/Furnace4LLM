## Onboarding checklist

- Participant alias/date, consenting note taker; assistance expected or not.
- Licence/authority to use model files; synthetic inputs, no confidential material.
- Windows/Docker Desktop working Linux containers, RAM/disk and optional NVIDIA access.
  Do not ask for global Docker changes.
- Exact candidate source/hash, unsigned-installer disclosure, uninstall/cleanup path.
  Use the release's install sheet, not this investor draft, for installation commands.
- Supported recipe or own adapter, pinned deps/code/weights, preparation downloads/cache.
  Stop at incompatibility; no secret host edits.
- Agree crash injection and cleanup of this disposable project only.
- Agree notes/recording scope; recordings and public case studies require separate consent.

During session observe purpose first, then inspect/export kit, approve prepare/start,
ask, evaluate, view health/logs, crash the demo model, restart explicitly, compare
outputs, export and stop. Record help, errors and expectations. Never mark unexecuted
steps successful. Keep failed sessions and exact elapsed setup/cache context.
