# Known limitations

- Pre-release local software. Paid operation, accounts, billing and remote control
  plane are proposals. Customer-compute operation also requires consent, secure
  remote access, updates and support; it is not already a service.
- Evidence includes unmerged candidates with retained source identity/dirty flags.
  This docs-only branch does not ship those features.
- Provisional installer acceptance covers Studio CPU, not both journeys on final
  identical bytes. Clean-account install, human comprehension and pilot remain
  separate. Hosted Ubuntu CI is the accepted Linux gate; local diagnostic failures
  have not been relabelled passes.
- No independently onboarded customer, willingness to pay, retention, institutional
  deployment or traction total is established by this room.
- Real outside-researcher adapter proof awaits freeze. Deterministic adapter tests
  and Granite through llama.cpp do not satisfy it.
- Models fail quality rules. Repeated output is not correctness. Mixed GPU source
  and installed CPU trials are not fair rankings or universal hardware-fit evidence.
- Containers narrow risk, not hostile Docker administrators, kernel flaws or image
  build dependencies. Checked records/logs/exports omit launch keys; Docker admins
  can inspect live environments. [Boundary snapshot](evidence/boundary.txt).
- A blocked public-destination probe is not every-destination reachability proof.
  Host/browser preparation downloads are outside inference network isolation.
- Injection detection/protection is heuristic, may miss attacks or flag valid text.
  Model answers require review. No compliance or universal security claim.
- Signing, final licence review, publication and hosted-service operations are not
  established by this kit. Market funnels and resource/support costs are assumptions.
- Competitors were researched from their documentation, not independently tested.
