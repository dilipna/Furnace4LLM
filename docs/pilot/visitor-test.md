# First-time visitor test (not yet run)

Use one nontechnical participant and one Python developer unfamiliar with Furnace.
Give each the website URL and no introduction to the product. Use a fresh browser
session. Ask permission to take notes; do not collect credentials, real private prompts
or repository content. Do not install an App or start inference in this exercise.

Say: “We are testing the website, not you. Please think aloud. I will avoid helping
unless you get stuck. There are no right answers you need to guess.”

## Five tasks

1. Start at the landing page. Explain what Furnace does, who it is for, and when it
   acts in your own words. Record what is understood after 30 seconds, without coaching.
2. Find the demonstration. Is it recorded or running now? Explain what changed and
   why the app slowed down. Try the text explanation as well as the video.
3. Find its result. What happened, and who decides whether the proposed fix is merged?
   Find “Functionally tested; performance unverified” and explain what it does **not** prove.
4. Determine whether your setup fits. Nontechnical participant: locate who would need
   to decide. Developer: use your own setup or this scenario—Python prompt builder,
   team-controlled remote vLLM server, Linux Docker, one authorized GitHub repository.
   Identify prerequisites, execution location, permissions and any uncertainty.
5. Find your correct next step without assistance. Developer: locate the first commands,
   success signal, recovery for an interrupted install, and stopping/removal steps.
   Nontechnical participant: find source/architecture or evidence limits, then decide
   what you would do next. No external action is required.

For recruiter/manager findability, note whether summary, demo, architecture, source,
evidence limits and implemented/planned distinction were found within two minutes.
Time goals are evaluation questions, not established usability results.
